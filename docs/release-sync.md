# Синхронизация версии Owl-IN ServiceKit

GitHub Pages получает сведения о последнем стабильном релизе при сборке сайта.
Workflow `deploy.yml` запускается при изменении сайта, вручную и каждые 15 минут.
Если версия, ссылки, размер и SHA-256 совпадают с опубликованным `release.json`,
повторная публикация по расписанию пропускается. Расписание GitHub Actions может
запускаться с задержкой.

При публикации нового релиза ServiceKit можно сразу запустить workflow сайта:

```sh
gh workflow run deploy.yml --repo Owl-IN-ex/Owl-IN-ex.github.io
```

В опубликованный HTML встроены актуальная версия, ссылка на EXE и SHA-256.
Браузер также читает `release.json` с этого же сайта и проверяет GitHub API.
Старые данные в кеше или медленный ответ источника не могут понизить показанную версию.
Если API GitHub недоступен на компьютере посетителя, страница остаётся актуальной
за счёт серверной сборки и файла на том же домене.

Для workflow используется встроенный `GITHUB_TOKEN` с минимальными разрешениями
`contents: read`, `pages: write` и `id-token: write`. Личный токен не требуется.
